# arknet-bounded-context

Vierte hexagonale BC (Bauart 1:1 zu requirements) -- arknet-bounded-context-core + arknet-bounded-context-adapter-kogniordf (Out) + arknet-bounded-context-adapter-mcp (In). Macht `arknet:BoundedContext` store-first mintbar (`bc_add`/`bc_list`/`bc_get`/`bc_link_term`), damit die Zuordnung Term<->BoundedContext gezogen werden kann (aus der #62-Entscheidung: Glossar bleibt projektweit, kein Scheme-pro-BC). Kein Ontologie-Delta -- das Metamodell trug `arknet:BoundedContext` + Properties (`arknet:name`, `arknet:domainVision`, `arknet:subdomain`, `arknet:ownedBy`, `arknet:hasAggregate`, `arknet:ubiquitousLanguageTerm`) und `shapes:BoundedContextShape` bereits. `bc_add` schreibt `name`+`domainVision` (SHACL-Pflicht) sowie optional `subdomain` (Enum `Subdomain` -> `arknet:CoreDomain`/`SupportingDomain`/`GenericDomain`, `sh:in`) und `ownedBy`. Opake Identitaet: `BoundedContextId` wrapt eine vom Kernel gemintete `ResourceId`, `BoundedContextCode` traegt die `BC-N`-Semantik als reines Business-Label (`dcterms:identifier`) -- der MCP-Nutzer tippt den Code. `save` zerfaellt in `create` (Identitaet neu, sonst `ResourceAlreadyExistsException`; Code-Kollision -> `DuplicateBoundedContextCodeException`) und `compareAndUpdate` (Identitaet muss existieren, sonst `BoundedContextNotFoundException`; erwarteter `arkprov:head` muss noch aktuell sein, sonst `BoundedContextConcurrentlyModifiedException`), Existenz-, Code- und Head-Check per `DatasetTx#contains` bzw. In-Tx-Read **innerhalb** der Schreibtransaktion (kein TOCTOU; `contains` statt SPARQL-`ASK`, weil ein `ASK`-Guard auf noch unbekannte IRIs unter SERIALIZABLE nicht konfliktgeschuetzt ist -- ADR-013-Nachtrag), replace-by-identity bleibt. Eine unbedingte Update-Methode gibt es am Out-Port nicht. `bc_link_term` zieht die Kante `arknet:BoundedContext arknet:ubiquitousLanguageTerm skos:Concept` -- Richtung BC->Term bewusst (#62): der nennende Kontext besitzt die Kante, Abhaengigkeit zeigt bounded-context -> ubiquitous-language. Die Kante steckt **im** `BoundedContext`-Record (`usesTerms`, `TermRef` haelt die Subject-`ResourceId`), nicht daneben -- sonst loescht der naechste replace-by-identity-Write sie still (Lehre aus req). Aufloesung Code -> Identitaet streng per `dcterms:identifier` hinter dem Out-Port `TermLookup` (Impl `KognioRdfTermLookup`, 1:1 zu req), didaktische Ablehnung ueber `UnresolvedReferenceException`; n:m (mehrere BCs duerfen denselben Term nennen). Anders als req `arkreq:usesTerm` traegt `arknet:ubiquitousLanguageTerm` **kein** `sh:class`-Constraint in der Shape, daher braucht der Out-Adapter **keinen** validation-only `assertedContext` -- `gate.enforce(graph)` genuegt. Der Out-Adapter bewahrt store-first Blank-Node-Kanten von `ubiquitousLanguageTerm` ueber den replace-by-identity-Schreibpfad (wie req #65); `arknet:hasAggregate` bewahrt er zusaetzlich **vollstaendig** (jede Kante, nicht nur Blank-Node-Ziele) -- `BoundedContext` fuehrt dafuer gar kein Domain-Feld, ein `bc_link_term`-Write wuerde sonst jede zuvor store-first gesetzte Aggregate-Zuordnung stillschweigend loeschen. Ausserdem gruppiert er `findAll`-Zeilen pro Subject (subdomain/ownedBy ohne durchsetzbaren `sh:maxCount`, #81-Muster, WARN bei kollabierten Mehrwerten). `add()` vergibt den naechsten `BC-N`-Code ueber den geteilten `CodeAssignment`-Retry (`arknet-shared-kernel`) und faengt so den TOCTOU-Race auf den naechsten freien Code bei parallelen `bc_add`-Aufrufen ab (#144, dieselbe Bauart wie req #108 -- Single-User heisst nicht Single-Writer, parallele Sessions eines Nutzers gegen denselben lokalen Store sind der Normalfall, ADR-001). `linkTerm()` laeuft ueber `updateWithOptimisticRetry`: Kernfelder **und** `arkprov:head` aus einem Snapshot (`findCurrentByCode`), `usesTerms` bewusst aus einem spaeteren, eigenen Read (kann nur frischer sein, nie staler als der Head), Mutation, `compareAndUpdate` mit dem beobachteten Head, bei Mismatch Retry gegen einen frischen Read (#176, Bauart 1:1 zu req #108/#167) -- ohne diesen Guard verloren zwei parallele `bc_link_term`-Aufrufe auf demselben BC still eine `ubiquitousLanguageTerm`-Kante. Das Token schuetzt Trichter-Schreiber gegeneinander, nicht gegen store-first-Edits am Trichter vorbei (ADR-014-Nachtrag). Kein `findByIds`/`ResolveBoundedContexts` (kein Nachbar-BC loest BC-Identitaeten auf). Anzeige-Rueckrichtung `ResourceId -> TERM-N` in `bc_get`/`bc_list` ueber den ul-In-Port `ResolveTerms` mit IRI-Fallback (`arknet-bounded-context-adapter-mcp` -> `arknet-ubiquitous-language-core`, ADR-008). SHACL: `shapes:BoundedContext-hasAggregate` von `sh:Violation` auf `sh:Warning` gesenkt (#66) -- ein store-first via `bc_add` gemienteter BC entsteht in der Analysephase VOR taktischem Design (Aggregates existieren noch nicht), die Severity darf das nicht blockieren; da das Gate nur `sh:Violation` sammelt, passiert ein BC ohne Aggregate den Write. Der Gate reasont nicht (Shape targetet `arknet:BoundedContext` direkt, leere Axiome + `ValidationOptions.defaults()`, wie ul).
