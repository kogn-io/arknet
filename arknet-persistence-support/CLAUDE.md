# arknet-persistence-support

Technischer Support der kognio-rdf-Out-Adapter -- das von allen BCs geteilte SHACL-Write-Gate (`de.hauschel.arknet.persistence.ShaclWriteGate` + `WriteConstraintViolationException`, validate-before-commit) und der geteilte Schreibtrichter `WriteFunnel` (ADR-013): das Transaktions-Skelett jedes bewachten Graph-Writes -- `create` (Gate -> acquire -> Tx mit Subject- und Code-`ASK` -> Body; Commit-Konflikt #144 wird in das `duplicateCode`-Signal uebersetzt) und `update` (Gate -> acquire -> Tx mit Subject-`ASK` -> Body; bewusst KEINE Konflikt-Uebersetzung, wie vor der Migration). Kontextunterschiede sind Parameter, kein Code im Trichter: BC-Exceptions kommen als `Supplier`-Signale, der Schreib-Body (inkl. aller Kantenbewahrung) als `Consumer<DatasetTx>` auf der vom Trichter besessenen Transaktion. Dieser Tx-Besitz traegt die Revisions-Basis (ADR-011/ADR-014): nach dem Body, in derselben Transaktion, schreibt der Trichter genau EINE immutable PROV-O-Revision (`prov:Activity` + `prov:Entity`/`arkprov:Revision` mit `prov:specializationOf`/`wasGeneratedBy`/`generatedAtTime`, Kette via `prov:wasRevisionOf`) und schreibt den `arkprov:head`-Pointer der Ressource fort -- alles in den eigenen Named Graph `ArkprovVocabulary.PROVENANCE_GRAPH` (getrennt von den Modell-Graphen, damit replace-by-identity-Bodies ihn nie treffen); ein abgelehnter oder fehlschlagender Write hinterlaesst keine Revision (Tx-Rollback). Der Head ist das abfragbare Concurrency-Token; der bedingte Write (Compare-and-Set auf erwarteten Head) ist NICHT implementiert. Die Activity traegt keinen aufgeloesten Agenten -- Agent-Attribution ist additiv (ADR-014 Entscheidung 5). Revisions-/Activity-IRIs muenzt der Trichter selbst, flach-opak unter `https://w3id.org/arknet/revision/` bzw. `.../activity/` (kein Kernel-Import). Ausserhalb des Trichters (und damit noch OHNE Revisionen) bleiben bewusst der Patch-`update` der ul-BC und `compareAndUpdate` der req-BC (eigene Tx-Semantik; ADR-013 Entscheidung 5) -- ihre Aufloesung in den Trichter ist ADR-014 Entscheidung 4. Zusaetzlich vier technologieneutrale, RDF4J-freie Bausteine: `SparqlTerms` (SPARQL-Escaping inkl. LF/CR/TAB + IRIREF-Serialisierung `isValidIriReference`/`iriRef`), `UnresolvedReferenceException` (didaktische Cross-BC-Ablehnung), `ArkprovVocabulary` (die IRIs des Revisions-Vokabulars als `String`-Konstanten -- Provenance-Graph, `arkprov:Revision`/`head`, PROV-O-Praedikate -- geteilt zwischen dem schreibenden Trichter und jedem Head-/Revisions-Lesepfad; Ontologie-Seite in `arknet-ontology/src/main/resources/arknet-provenance.ttl`) und `ArkreqVocabulary` (die sechs geteilten `arkreq:`-Objekt-Praedikat-IRIs `usesTerm`/`primaryActor`/`supportingActor`/`mainStep`/`extensionStep`/`stepRealises` sowie die vier geteilten Typ-IRIs `FunctionalRequirement`/`NonFunctionalRequirement`/`Step`/`skos:Concept` als `String`-Konstanten -- die einzige Quelle, aus der sowohl die `*-adapter-kogniordf`-Out-Adapter diese Kanten/Typen serialisieren als auch `arknet-mcp`s Traceability-Lesepfad sie traversiert/testet; RDF-Serialisierungskonstanten, kein Domain-Vokabular, da die Cores dank opaker Identitaet nie IRIs sehen -- sie wohnen darum bei `SparqlTerms`, nicht im Kernel; als reine Strings bleibt das Modul RDF4J-frei). Das Gate traegt zusaetzlich einen `enforce(candidate, assertedContext)`-Overload: validation-only Kontext-Tripel (synthetische Typen fuer Nachbar-Graph-Knoten) als **Parameter** -- weiterhin kein Kontextwissen im Gate (ADR-007). Bewusst KEIN Shared Kernel: der Kernel wird von den `*-core` konsumiert und muss dependency-frei bleiben, das Gate nur von den `*-adapter-kogniordf` -- ein Merge zoege die kognio-rdf-Ports in den Classpath der Cores. Die Trennung ist lasttragend, nicht Geschmack (hier wohnt zudem Technik, kein Domain-Vokabular). Trotz kognio-rdf-Abhaengigkeit RDF4J-frei -- das Gate kennt nur die `io.kogn.rdf.shacl`/`terms`-Ports, RDF4J bleibt in den Repository-Factories. Kontextunterschiede sind Konstruktor-Parameter (`shapes`/`axioms`/`options`), **kein Code im Gate**: req reasont ueber die Axiome (`subClassOf`, volle Shapes), ul uebergibt leere Axiome + `defaults()` (kein Reasoning), uc konstruiert Axiome/Options identisch zu req -- sein echter Unterschied sind **gefilterte** Shapes (`loadUseCaseShapes()` entfernt fremde `sh:targetClass`), und diese Filterung ist Code in der uc-Factory. Siehe ADR-007.
